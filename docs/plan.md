# План работ (v1)

Каждый шаг заканчивается тем, что можно открыть и проверить. ☐ — не начато, ◐ — в работе, ☑ — готово.

## Этап 0. Подготовка
- ☑ 0.1 Каркас Angular 22 + SCSS, git, ESLint. *Проверка:* `ng serve` открывает пустую страницу.
- ☑ 0.2 Дизайн-токены из DESIGN.md (CSS-переменные), шрифты Inter/JetBrains Mono, базовые компоненты: кнопки, карточка, бейдж, поле ввода, таблица. *Проверка:* страница-витрина `/dev/ui`.
- ☑ 0.3 Оболочка: шапка (лого, меню, RU/EN, вход), подвал, роутинг, Transloco. *Проверка:* переключение языка без перезагрузки.
- ☑ 0.4 **[ты]** Аккаунт Supabase, проект; **[ты]** ключ Steam Web API. Я — схема БД (миграции), RLS, тестовые данные.

## Этап 1. Логика (без UI)
- ☑ 1.1 Чистые функции подсчёта (spec §5) + юнит-тесты: квалификация, посев/баи, дуэль/OMT, места, очки, команды, сезон.

## Этап 2. Вход и профиль
- ☑ 2.1 Edge Function `steam-auth`, кнопка входа, сессия. *Проверка:* вхожу своим Steam, вижу ник и аватар.
- ☑ 2.2 Личный кабинет `/me`: выбор номера (сетка + случайный), машина (двигатель, КПП, мощность), ливрея (загрузка + сжатие), о себе. *Проверка:* организатор сохраняет номер, машину и ливрею.

## Этап 3. Админка сезона и этапа
- ☑ 3.1 Сезоны: создание, таблицы очков, статусы.
- ☑ 3.2 Этапы: настройки (веса, судьи, сетка), открытие регистрации.
- ☑ 3.3 Регистрация пилота на этап; в админке — группы и очередь (перетаскивание).
- ◐ 3.4 Команды: создание, заявки, капитан, подтверждение.

## Этап 4. Пульт судьи
- ☐ 4.1 Квалификация: очередь, 3 поля, Спин/Дисконнект/Техпоражение, живая таблица.
- ☐ 4.2 Сетка: автопостроение, баи; дуэли: голоса, OMT, техпоражение, продвижение, дуэль за 3-е.
- ☐ 4.3 Протесты: кнопка у проигравшего (5 мин, ≤ 2 за этап, видео + описание); уведомления admin (значок, всплывашка, Discord); решения: отклонить / отдать победу / перезаезд; блок следующей дуэли до решения.
- ☐ 4.4 Завершение этапа → `stage_results`, очки, достижения. Команду пилота брать из подтверждённого состава сезона на момент завершения (снимок в `registrations` мог устареть).
