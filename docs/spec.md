# Спецификация: сайт Sad Drift Series (v1)

Основа — [docs/intent/sds-site.md](intent/sds-site.md). Дизайн — [DESIGN.md](../DESIGN.md). Регламент SDS v2.0.

## 1. Стек

| Часть | Выбор | Почему |
|---|---|---|
| Фронтенд | Angular 22 (standalone, signals), SCSS | Организатор знает Angular |
| i18n | Transloco (переключение без перезагрузки) | RU по умолчанию, EN переключателем |
| Бэкенд | Supabase: Postgres + Auth + Realtime + Storage + Edge Functions | Бесплатно, без карты, realtime для плашек |
| Хостинг | Netlify (SPA) + свой домен | Бесплатно |
| Вход | Steam OpenID 2.0 через Edge Function `steam-auth` | Только Steam |

Без UI-библиотек: компоненты свои по DESIGN.md. Графики (паутинка) — inline SVG. Картинка FIFA-карточки — `html-to-image`.

## 2. Роли и доступ

| Роль | Кто | Может |
|---|---|---|
| `admin` | Организатор | Всё: сезоны, этапы, роли, спонсоры, санкции, настройки |
| `staff` | Судьи, управляющий трансляцией | Пульт этапа (оценки, голоса, очередь), пульт плашек, видит санкции |
| капитан | Пилот с `teams.captain_id` | Приглашать/убирать пилотов своей команды (заявки подтверждает admin) |
| `pilot` | Любой вошедший через Steam | Свой профиль, регистрация на этап, заявка в команду |
| зритель | Без входа | Всё публичное |

Права проверяются в Postgres через RLS — фронт только прячет кнопки.

## 3. Вход через Steam

1. Кнопка «Войти через Steam» → Edge Function `steam-auth/start` → редирект на `steamcommunity.com/openid/login`.
2. Steam возвращает на `steam-auth/callback`; функция проверяет ответ (`openid.mode=check_authentication`), достаёт SteamID64.
3. `GetPlayerSummaries` (секрет `STEAM_API_KEY`) → ник + аватар (full).
4. Создаёт/находит пользователя Supabase (`<steamid>@steam.sds`), обновляет `profiles` (ник/аватар — при каждом входе).
5. Генерирует magic-link токен (`auth.admin.generateLink`) и редиректит на сайт `/auth/callback?token_hash=…`; фронт вызывает `verifyOtp` → сессия.

Требование: ключ Steam Web API (аккаунт с покупками ≥ $5).

## 5. Правила подсчёта (чистые TS-функции + юнит-тесты)

### 5.1 Квалификация
- Порядок: группы → `queue_order` внутри группы.
- Попытка 0 — прогрев, не оценивается. Попытки 1 и 2: судья угла/стиля/траектории ставит балл от 0 до `weights.<критерий>`. `total = angle + style + line` (≤ 100).
- **Спин** → total попытки = 0.
- **Дисконнект** → пилот уходит в конец очереди, оставшиеся попытки — после всех. По своей вине → техпоражение (без результата).
- Результат пилота = max(попытка 1, попытка 2).
- Места по убыванию результата. **Ничья:** выше тот, у кого выше худшая из двух попыток; дальше — по `queue_order` (решение организатора, см. §10).

### 5.2 Сетка
- Размер: `auto` → 32 при N ≥ 17, 16 при 9–16, 8 при ≤ 8 (N — пилоты с результатом). Можно задать вручную.
- Посев — классический (1–32, 16–17, 8–25 …), так что 1 и 2 встречаются только в финале.
- Если N < размера: посевы 1…(размер − N) проходят первый раунд по баю (`result=bye`).
- Лидер в паре — пилот с лучшим местом квалификации.

### 5.3 Дуэль
- 2 заезда (лидер меняется), затем каждый из 3 судей голосует `leader | chaser | omt`.
- ≥ 2 голоса за пилота → победа. Иначе OMT (`omt_count + 1`), новое голосование (`try`).
- После OMT №2 без решения → побеждает лучший по квалификации (`result=qual_tiebreak`).
- Техпоражение — кнопкой (`result=tech_loss`). Дисконнект — перезаезд дуэли (просто новое голосование того же `try`).
- Победитель автоматически попадает в следующий слот; проигравшие полуфиналов — в дуэль за 3-е место.

### 5.4 Места на этапе
- Дуэли: 1 — победитель финала, 2 — финалист, 3/4 — дуэль за 3-е, 5–8 — проигравшие в Top 8, 9–16 — в Top 16, 17–32 — в Top 32.
- Не прошедшие в сетку — места по квалификации (33+).
- Итоговое место внутри группы мест (5–8 и т.п.) — по месту в квалификации.
- Пилот с DQ на этапе — 0 очков, не классифицируется.

### 5.5 Очки (по умолчанию RDS GP 2024, хранятся в `seasons`)
- Квалификация: 1→22, 2→19, 3→17, 4→15, 5→14, 6→13, 7→12, 8→11, 9→10, 10→9, 11→8, 12→7, 13→6, 14→5, 15→4, 16→3, 17–32→2, 33+→1.
- Дуэли: 1→250, 2→180, 3→145, 4→120, 5–8→70, 9–16→30.
- Очки пилота за этап = квалификация + дуэли.
- Команда за этап = сумма `team_counted` (3) лучших пилотов команды. Ничья — у кого пилот выше в личном зачёте этапа.

### 5.6 Сезон
- Личный зачёт = сумма очков за этапы. Ничья: больше 1-х мест, затем 2-х, … → больше побед в квалификации → выше место на последнем этапе.
- Командный = сумма командных очков за этапы. Ничья — у кого лучший пилот выше в личном зачёте.
- «Завершить сезон» (admin) → фиксирует чемпионов, статус `finished`, сезон в архиве.

### 5.7 Завершение этапа
Кнопка «Завершить этап» (admin) → считает `stage_results`, выдаёт достижения, шлёт Discord-итоги, статус `finished`. Можно пересчитать повторно.

## 6. Страницы

### Публичные (RU/EN)
| Путь | Что |
|---|---|
| `/` | Герой «ночной тоге»; текущий/следующий этап (таймер или LIVE + Twitch + живая пара/таблица); лидеры сезона (топ-5 пилотов, топ-3 команды); спонсоры |
| `/standings` | Личный и командный зачёт сезона (выбор сезона) |
| `/stages` , `/stages/:id` | Список этапов сезона; этап: инфо, квалификация, сетка, итоги (живые во время этапа) |
| `/pilots` , `/pilots/:steamId` | Пилоты; профиль: номер, аватар, ливрея-обложка, команда, статистика, паутинка, достижения, история этапов, FIFA-карточка (скачать) |
| `/teams` , `/teams/:id` | Команды; состав, очки, история |
| `/archive` | Прошлые сезоны и чемпионы |
| `/rules` | Регламент (RU/EN, версия) |

### Личный кабинет (RU/EN)
`/me` — профиль (номер, ливрея, о себе), регистрация на этап, моя команда (заявка; капитан — состав), мои достижения.

### Служебные (только RU)
| Путь | Роль | Что |
|---|---|---|
| `/admin/seasons` | admin | Сезоны, таблицы очков, завершение сезона |
| `/admin/stages/:id` | admin | Настройки этапа: веса, судьи, размер сетки, регистрации, группы и очередь (drag & drop) |
| `/admin/judge/:stageId` | staff | Пульт: текущий пилот/попытка → 3 поля → «Сохранить»; кнопки Спин / Дисконнект / Техпоражение; потом сетка → голоса 3 судей → OMT/победа |
| `/admin/broadcast` | staff | Пульт плашек: показать/скрыть каждую, язык, превью 16:9 |
| `/admin/pilots` , `/admin/teams` | admin | Роли, номера, заявки в команды, санкции |
| `/admin/sponsors` | admin | CRUD спонсоров |
| `/admin/settings` | admin | Twitch-канал, Discord-вебхук, регламент |

Пульт судьи сам ведёт по очереди: после сохранения — следующий пилот; в дуэлях — следующая пара. Ошибку можно исправить в любой момент (правка пересчитывает места).

### Плашки OBS
`/overlay` — прозрачный фон, 1920×1080, без шапки. Слушает `overlay_state` и данные этапа через Realtime. Виджеты:
стадия (угол), «на трассе», оценка заезда (счётчик), таблица квалификации, карточка дуэли (+ голоса судей по одному), сетка на весь экран, подиум, ротация спонсоров.
`/overlay?only=<widget>` — один виджет, если нужно раскладывать по разным источникам в OBS.

## 7. Фишки v1
- **Достижения:** first_win, perfect_100 (100 в квалификации), qual_king (1-е место в квалификации), survived_omt2, hat_trick (3 победы этапов подряд), podium. Выдаются при завершении этапа.
- **Паутинка:** средние доли угол/стиль/траектория от максимума по зачётным попыткам сезона.
- **FIFA-карточка:** номер, аватар, ливрея, рейтинг (средний % квалификации), 3 критерия, команда; кнопка «Скачать PNG».
- **Discord:** Edge Function `discord-notify` — открыта регистрация, старт этапа, итоги этапа, новый лидер сезона.

## 8. Нефункциональное
- Адаптив от 320px; пульт судьи — от 1024px.
- Доступность: фокус, контраст AA, `prefers-reduced-motion`.
- Плашки обновляются < 1 с после действия.
- Бесплатные лимиты: Supabase 500 МБ БД, 1 ГБ Storage — ливреи сжимаем до ≤ 500 КБ на клиенте.

## 9. Тесты
- Юнит-тесты на чистые функции: результат квалификации, места и ничьи, посев и баи, исход дуэли/OMT, места этапа, очки, командный зачёт, тай-брейки сезона.
- Ручная проверка: прогнать тестовый этап на 20 пилотов от регистрации до итогов и плашек.
