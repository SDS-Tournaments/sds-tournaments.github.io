# Как работаем

## Цикл изменения
1. Правка → `npx ng build --configuration development` (быстрая проверка) → `npx ng test --watch=false`.
2. Проверка вживую на `http://127.0.0.1:4200` (dev-сервер в фоне, перезапускать не нужно — HMR).
3. `git commit` локально, сообщение на английском, в конце строка `Co-Authored-By: …` (из системного напоминания).
4. Рассказать владельцу по-русски: что сделано, что проверено, что **не** проверено и где посмотреть.
5. **Пушим только по команде «заливай»** (несколько правок — одним пушем). Перед пушем — чек-лист ниже.
6. После пуша — дождаться выкладки (≈45–90 с) и проверить прод: опрашивать curl'ом признак новой версии
   (например, новый ключ в `https://sds-tournaments.github.io/i18n/ru.json` или файл), затем открыть страницу.
   `gh` CLI не установлен — статус Actions напрямую не посмотреть.

## Чек-лист перед «заливай»
- [ ] `npx ng test --watch=false` зелёный, `npx ng build` (прод) собирается (предупреждение бюджета overlay.scss — известное).
- [ ] Миграции, от которых зависит код, выполнены на **боевой** базе (проверка: `curl …/rest/v1/<table>?select=<col>&apikey=<publishable>` →
      200 `[]` значит колонка есть; 400 `42703` — нет). Для приватных таблиц RLS вернёт `[]`, но ошибка колонки всё равно видна.
- [ ] Если менялась edge-функция — владелец задеплоил её (команды ниже), иначе предупредить, что поведение будет старым.
- [ ] **Обновлена вики** (затронутые страницы + запись в [changelog.md](changelog.md)) и закоммичена.
- [ ] `git status` чистый, `git push`.

## Команды
```bash
npx ng serve --host 127.0.0.1 --port 4200                         # прод-база
npx ng serve --configuration staging --host 127.0.0.1 --port 4201 # тестовая база
npx ng test --watch=false
npx ng build                                                      # прод-сборка (как в CI)
npx ng build --configuration development                          # быстрая проверка компиляции
```
CI (`pages.yml`): `npm ci` → тесты → сборка → копии `index.html` в `404.html`, `<раздел>.html` (stages, standings, pilots, teams, rules, archive, me)
и `auth/callback.html`, `auth/steam.html` — чтобы прямые ссылки отдавались с кодом 200. Остальные адреса (например `/attack-shark`,
`/pilots/:id`) работают через `404.html` (код 404, но страница открывается; поисковики такие не индексируют).

## Миграции
- Файлы: `supabase/migrations/NNNN_name.sql` (следующий номер — 0022). Идемпотентно, где можно (`if not exists`).
- Владельцу даём **текст SQL прямо в сообщении** (не путь к файлу) — он вставляет в Supabase → SQL Editor.
  Выполнять на **обеих** базах: сначала тестовая, потом боевая.
- Код, зависящий от новой колонки, не заливать, пока миграция не прошла на проде (иначе select с колонкой падает целиком).

## Edge-функции
Деплоит **владелец** (автоматический режим блокировал прод-деплой). Даём команды:
```bash
npx supabase functions deploy discord-notify --project-ref dghjrbxffsmmdalzdycz
npx supabase functions deploy steam-auth --no-verify-jwt --project-ref dghjrbxffsmmdalzdycz
npx supabase functions deploy test-pilots --project-ref dghjrbxffsmmdalzdycz
```
Для staging — `--project-ref oqmepaxnccxqupemvewy`. `steam-auth` всегда с `--no-verify-jwt` (Steam возвращает без токена).

## Приёмы правки файлов
- Многострочные правки — Node-скриптом из scratchpad, записанным через Write (heredoc в bash ломается на кавычках,
  обратных кавычках и `${}`). В скрипте: читать, `replace(/\r\n/g,'\n')`, `rep(a,b)` с проверкой «нашлось», писать.
- Точечные правки — Edit (нужен Read файла перед этим).
- **JSON переводов не пересобирать через `JSON.stringify` всего файла** — он развернёт компактные объекты (ачивки) в многострочные.
  Вставлять блок текстом перед последней `}` или заменять строку; после — `JSON.parse` для проверки.
- Предупреждения git «LF will be replaced by CRLF» — нормально.

## Приёмы проверки в браузере (встроенная панель)
- Панель часто скрыта: **rAF и анимации стоят**, скриншоты могут отставать на кадр. Поэтому:
  - убрать загрузочный экран: `document.getElementById('boot')?.remove()`;
  - доиграть анимации: `document.getAnimations().forEach(a=>{try{a.finish()}catch{}})`;
  - кадр из середины: `el.getAnimations().forEach(a=>{a.pause(); a.currentTime=150})`;
  - проверять цифрами (`getBoundingClientRect`, `getComputedStyle`) — ширины, наложения, отступы.
- Увеличенный скриншот: `document.body.style.zoom=3` (у `documentElement.zoom` скриншот не меняется); потом вернуть `''`.
- Ширины экрана: `resize_window` с `preset: mobile|desktop` или своими размерами; **сбросить в desktop** после проверки.
- Вид для залогиненного без входа (только локально, в базу ничего не пишется):
  `const app=ng.getComponent(document.querySelector('app-root')); app.auth.profile.set({...профиль, role:'admin', discord:null}); app.auth.ready.set(true)`,
  навигация — `app.router.navigateByUrl('/me')` (полная перезагрузка сбросит подмену). Кнопки «Сохранить» так не жать — RLS не пустит.
- Медленная загрузка: подменить `window.fetch` задержкой и перейти по ссылке внутри SPA — увидеть лоадер.
- Наведение: `computer` → `hover` по координатам скриншота (кадр 800px ≠ CSS-пиксели; масштаб = innerWidth/800).
- Длинные анимации (полёт, плавность) вживую не видно — честно писать владельцу, что проверены кадры, а не движение.

## Общение с владельцем
- По-русски, коротко: что сделал → что проверил → что посмотреть (ссылка на 127.0.0.1) → одна-две строки «что не проверял и риски».
- SQL — блоком текста. Команды — блоком `bash`.
- Если запрос двусмысленный («исправь улетание в левую сторону») — выбрать трактовку, сказать какую, предложить поменять одной строкой.
